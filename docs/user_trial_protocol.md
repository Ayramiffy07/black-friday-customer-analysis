# Retail Insight：首次用户试用方案

状态：方案与记录模板，尚未开展用户访谈或形成效果数据。目标邀请2–3名有运营或取数经验的人；找不到目标用户时如实标注为同伴可用性测试。

## 需求假设

目标用户为不熟悉SQL的运营人员，希望查询客群消费贡献并解释分母。现有替代方式可能是固定报表、筛选表单或请分析师取数，这些是待访谈确认的假设。数据是匿名Black Friday购买记录，不是目标企业的门店销售数据。

## 任务与成功标准

| 任务 | 成功标准 |
| --- | --- |
| 查哪个客群贡献最高 | 找到排名第一客群及全体占比，能说清分母 |
| 查18–25岁女性占该年龄段消费的比例 | 条件与分母正确，能核查SQL证据 |
| 换一种口语表达查询 | 区分规则版与模型版；失败如实记录，不现场暗示答案 |
| 问一个时间趋势问题 | 理解为什么不能回答，没有把其他数字当成趋势 |
| 比较人数和人均消费并导出 | 不把总消费最高直接等同于人均最高或投放增量，成功下载结果 |

每次模型提交可能扣除额度，先征得试用者同意，不输入个人/客户敏感数据。演示者设置单次试用范围，停止条件为连续两次服务异常或达到会话上限。

## 记录（每位参与者单独复制填写）

- 日期、匿名编号、角色及相关经验：待填写。
- 原来如何完成同类任务、是否真的需要自然语言：待填写。
- 每项任务：是否独立完成、开始/结束时间、提示次数、错误理解及卡点：待填写。
- 是否能解释占比分母和数据来源：待填写。
- 原始反馈及对应改进：待填写，不把演示者推测当作用户原话。
- 是否更愿意使用筛选表单，为什么：待填写。

## 复盘规则

不凭2–3人推断市场需求。若没有可比基线时间，不计算“效率提升”；不把开发者演示成功算成用户独立完成。保留失败任务，优先修条件理解与口径问题。试用后形成问题优先级、修改依据和再次验证记录。
