# 本地受控模型网页试用

使用场景：个人演示与用户试用，尚不是公开付费服务。已有在线页面不受本地改动影响。

## 启动

在已设置 DEEPSEEK_API_KEY 的同一 PowerShell 中设置 RETAIL_ENABLE_MODEL=1 与 RETAIL_CONNECTION_MODE=direct，再运行 `python -m streamlit run app.py --server.address 127.0.0.1`。密钥只放环境变量，不写进代码、聊天或截图。只设置启用标志不会发起调用。

默认使用规则模式。侧栏选择模型试用后，客群问题由模型提取受控参数再执行 SQL；“指标知识问答 · RAG”则先检索批准知识库，再由模型生成带引用回答。每次提交最多一次真实请求；选择示例、切换排序、下载或刷新不触发请求。条件表单、默认概览、男女对比和多指标分析仍使用规则/SQL，不能把这些结果当作模型生成。

## 成本与边界

每会话最多5次模型提交，包括失败尝试；刷新或新会话可能重置，不是全局预算或滥用防护。不要把这套本地控制直接作为公开付费入口。当前模型模式仅通过环境开关显式启用，默认关闭，不读取云端Secrets。

## 试用任务

1. 规则模式输入“18至25岁的姑娘在全部消费里占多少？”，记录结果。
2. 模型模式提交同一句，查看查询计划的年龄、性别、分母及金额来源。
3. 输入需要日期的查询，应说明不支持。
4. 模型失败时应显示错误，不把规则答案伪装成模型成功。
5. 下载、切换图表时不应多扣一次调用。
6. 在 RAG 区输入“购买记录数是不是订单数？”，核对答案、文档 ID、章节、原文、提示词版本和 tokens。
7. 在 RAG 区询问天气或企业退货制度，应在模型调用前拒答。

结果包含本条响应的模式与来源，避免切换模式后把旧结果误认为新模式输出。当前无对话记忆，条件遗漏需重新补完整提问。
