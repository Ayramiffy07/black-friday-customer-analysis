# 零售 AI 经营分析助手：首版范围与验收

项目性质：个人 To B 场景原型，尚无实际客户部署或业务收益。

## 用户与问题

目标用户为零售运营经理。用户希望用自然语言查询客群贡献，并理解结果的口径与局限。后续需通过用户访谈验证需求，目前是产品假设。

## 第一个交付场景

用户问：“不同年龄和性别的客群，分别贡献多少消费额？”

流程：识别为客群贡献问题 → 执行已批准的 SQL → 返回结果表 → 解释贡献与人数 → 展示来源和口径。首版采用固定查询，模型不自行计算金额。

当前已实现 SQL/Pandas 对账、规则问答、受控模型参数解析、本地模式切换与界面。模型不生成数值解释，结果由程序模板呈现。公开站仍为规则版；企业权限、客户部署和持久化预算控制尚未实现。

## 指标契约

| 字段 | 口径 |
| --- | --- |
| user_count | 客群内去重 User_ID 数 |
| record_count | 客群内购买记录数，不是订单数 |
| total_purchase | 客群 Purchase 之和，原始数据单位 |
| average_purchase | 每条记录的平均 Purchase，不是人均消费 |
| share_of_all_purchase | 客群消费额 / 数据集全体消费额 |

分组字段为 Age 与 Gender，不包含日期筛选。每名用户的年龄和性别须一致。

## 首版回答规则

- 返回数值来自 SQL 结果；百分比仅在展示时四舍五入。
- 声明数据来源、查询文件、指标定义与没有日期的限制。
- 用户问“核心客群”时，说明按消费贡献排序，不能等同于利润或未来价值。
- 问“昨天/本月”的数据：说明无日期字段，不能支持。
- 问复购率或订单频次：说明无订单和日期，不能支持。
- 问商品类别名称：说明脱敏编码，不能推断。

## 数据层验收

1. 导入行数与原始 CSV 一致。
2. 必需字段完整，同一用户的分组属性一致。
3. SQL 与 Pandas 的人数、记录数、消费额、平均值与占比逐项一致。
4. 各客群消费占比合计为 1（允许浮点误差）。
5. 输出结果与核验记录可重跑生成。
