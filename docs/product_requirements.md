# Retail Insight 产品需求文档（PRD v1.0）

文档状态：作品集项目需求基线  
产品形态：面向零售运营取数场景的个人 To B 原型  
验证状态：已完成数据、SQL 与受控模型路径验证；尚无企业客户、真实业务收益或生产部署验证

## 1. 背景与问题

零售运营人员在查看客群消费贡献时，可能需要依赖固定报表、手工筛选或请分析人员取数。由此产生三个待验证的问题：

1. 非 SQL 用户从业务问题到查询条件的转换成本较高。
2. “全体占比”和“同年龄段占比”等指标分母容易混淆。
3. 查询结果与 SQL、数据范围、指标定义之间缺少可追溯证据。

以上来自作品集场景假设，并非客户访谈结论。首次用户试用按 `docs/user_trial_protocol.md` 执行。

## 2. 目标用户与核心任务

### 2.1 目标用户

- 主要用户：需要查看客群指标、但不一定会写 SQL 的零售运营人员。
- 次要用户：需要核查指标口径与查询依据的数据分析人员。

### 2.2 核心任务

- 查询不同年龄和性别客群的消费贡献。
- 区分客群总消费、用户数、记录数、人均消费及不同占比分母。
- 查看本次查询使用的条件、SQL 证据和数据限制。
- 导出查询结果与查询凭据，供复核或后续沟通。
- 查询指标定义、数据边界和操作说明，并获得带来源的回答（RAG 阶段）。

## 3. 产品目标与非目标

### 3.1 当前目标

1. 将自然语言问题转换为有限、可校验的查询参数。
2. 所有数值由参数化 SQL 计算，不由模型编造。
3. 对缺失条件、口径冲突和超出数据范围的问题进行澄清或拒答。
4. 让用户能够查看指标口径、数据来源、查询条件和证据。
5. 用冻结评测比较规则解析与模型解析的表现。

### 3.2 非目标

- 不开放自由 SQL 生成或任意数据库访问。
- 不预测销量、利润或用户未来价值。
- 不回答数据中不存在的时间趋势、订单频次或复购率。
- 不把探索性关联解释为因果关系或已验证的运营收益。
- 不将公开数据原型描述为真实企业生产系统。
- RAG 不用于检索 55 万条交易记录；结构化指标仍由 SQL 计算。

## 4. 数据与指标范围

数据来自公开 Black Friday 购买记录，共 550,068 条记录、5,891 名用户。数据没有日期、订单编号、成本和利润字段，商品类别为匿名编码。

| 指标 | 定义 | 主要限制 |
| --- | --- | --- |
| 客群用户数 | 客群内去重 `User_ID` 数 | 不代表活跃用户数 |
| 购买记录数 | 客群内记录行数 | 不等于订单数或购买频次 |
| 客群累计消费额 | 客群 `Purchase` 之和 | 金额沿用原始数据单位，不能直接称人民币 |
| 每条记录平均消费 | 客群消费额 / 记录数 | 不等于人均消费 |
| 人均累计消费 | 客群消费额 / 客群用户数 | 仅限本数据集累计值 |
| 全体消费占比 | 客群消费额 / 全体消费额 | 分母为全部年龄和性别 |
| 年龄段内消费占比 | 客群消费额 / 同年龄段消费额 | 必须明确年龄段 |

## 5. 核心用户流程

### 5.1 指标查询流程

```text
用户输入业务问题
  → 规则或模型提取 intent / age / gender / denominator
  → 程序校验字段、枚举与口径冲突
  → 执行批准的参数化 SQL
  → 返回结果、条件确认、指标口径、SQL 证据与导出文件
```

### 5.2 知识问答流程（计划增加）

```text
用户询问指标定义、数据限制或产品使用方法
  → 识别为知识问答
  → 从受控知识库检索相关文档片段
  → 仅基于命中文档生成回答
  → 展示来源文件、章节与拒答原因
```

数值查询与知识问答必须分流：前者走 SQL，后者走 RAG。若问题同时包含数值和定义，分别返回 SQL 结果与知识来源，不允许 RAG 片段替代数值计算。

## 7. RAG 知识库范围

首版知识库只收录本项目可证实的内容：

1. 指标字典：字段定义、公式、分母和易混淆项。
2. 数据说明：来源、字段、缺失、匿名类别和适用边界。
3. 产品使用说明：支持的问题类型、示例、导出和模式说明。
4. 分析限制：无日期、无订单、无利润及不可做的推断。
5. 验收说明：评测范围、评分方法和不能外推的结论。

不收录未经确认的企业制度、业务 SOP、商品含义或运营效果。每个知识片段需包含 `doc_id`、标题、章节、正文和版本；回答必须回传命中来源。

## 8. 异常与安全要求

- 模型返回额外字段、非法枚举、非 JSON 或语义冲突时，不执行查询。
- 模型/API 超时或失败时明确提示，不静默伪装为模型成功。
- 不把 API Key 写入代码、文档、日志或导出文件。
- 用户输入不得直接拼接到 SQL；只允许经过白名单校验的参数。
- 知识库无相关证据时回答“现有资料无法确认”，并建议可查询范围。
- RAG 回答中的数字若不是文档固定口径，不得作为实时指标输出。

## 9. 成功指标

### 9.1 离线质量指标

- 查询意图/参数符合预期率。
- 应答题 SQL 数值一致率。
- 澄清与拒答理由人工复核通过率。
- RAG 文档命中率、引用正确率、答案要点覆盖率、无依据拒答率。
- 请求失败率、端到端耗时中位数与 token 用量。

### 9.2 用户试用指标

- 任务独立完成率。
- 条件和分母理解正确率。
- 每项任务完成时间与提示次数。
- 用户选择自然语言、筛选表单或原有方式的原因。

在没有真实基线前，不宣称节省工时或提升销售。

## 10. 已有验证证据

- 原 15 条固定验收通过。
- 冻结 20 题中，规则版符合预期 10/20；模型＋程序校验路径 20/20。
- 其中 19 题由模型生成受控计划，1 题由程序双分母护栏澄清。
- 6 个数值应答题的目标金额与比例核验一致。
- 该评测集由 AI 编写，样本较小且不是外部独立评测，不能称为生产准确率 100%。

详细结果见 `reports/holdout_v1_report.md`。

## 11. 里程碑

1. PRD 基线：统一目标用户、范围、流程、指标和验收标准。
2. 知识整理：把指标、数据边界和操作说明整理为带版本的知识条目。
3. RAG 最小闭环：查询分流、检索、引用和无依据拒答。
4. RAG 对照评测：关键词基线与向量方案用同一批问题比较。
5. Demo 整合：在本地界面展示 SQL 路径或知识路径及来源。
6. 用户试用：记录真实任务、困难和对应迭代，不虚构反馈。
7. 作品集更新：以实际评测和试用结果更新 README、简历与演示材料。
