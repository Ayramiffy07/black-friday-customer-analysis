# 新版验收集：先审题，再冻结，再运行

20题位于 evals/query_holdout_v1.json。当前尚未运行，也没有因这些题修改提示词。它是AI编写的新验收集，不能宣称外部独立第三方测评；需要用户审阅预期口径。若根据结果优化实现，v1随即成为回归集，后续须新建验收集。

## 审阅要点

- H01–H06：应返回排名或单客群金额及对应分母；验证数值对账。
- H07–H10、H19：条件不完整、自定义年龄、多客群或依赖上下文，应请求澄清。
- H11：同时要求两分母，当前功能一次仅支持一个，需拆分；它不是用户表达错误。
- H12–H17、H20：时间、未支持指标或维度、SQL执行请求，不能丢条件后返回消费贡献。
- H18：解释消费贡献口径。

全部题目前向用户明确：当前自然语言入口只支持贡献查询；网页另有规则多指标分析，并不意味着模型入口支持所有指标。

## 冻结与运行（无须立刻调用API）

1. 人工核对问题与预期。有异议先修题，不执行模型。
2. 运行 `python scripts/freeze_evaluation.py`，保存提示词、路由、SQL、数据快照、评测器和题目的指纹，不覆盖旧冻结。
3. 先跑规则：`python scripts/evaluate_query.py --suite holdout --mode rule --limit 20`。
4. 用户确认后才跑模型，分批显式指定H题号、直连、allow-paid；每批最多5次，记录实际usage。调用失败不得隐去重测后只选成功；与开发汇总分开。
5. 报告逐题正确率、澄清与不支持识别、应答题数值一致性、调用失败率、端到端耗时分布及tokens。分别标记程序护栏与模型决策。

当前程序尚无全局30元扣费硬上限；公开页继续关闭模型功能。测试通过不等于真实客户已验收。
