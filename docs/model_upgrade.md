# 模型升级：受控解析与对照验证

## 目的和当前状态

数值查询中，模型仅解析查询意图与参数，程序校验后调用原有 SQL；不生成 SQL、不获取用户明细、不生成计算结果。规则版保持不变。本地网页已通过环境开关启用受控模型试用，并增加独立 RAG 知识问答入口；公开网页仍不开放付费模型调用。

基线：15条固定规则验收均通过，云端汇总与本地5个场景结果一致；冻结20题中规则版10/20，受控模型与程序校验路径20/20。RAG可见开发集关键词检索12/12，真实模型v1人工复核11/12，保留失败后以v2定向修复。以上均为开发证据，不是生产准确率或外部独立评测。

## 查询契约

模型只能返回 intent、age、gender、denominator、reason。允许全体排名、单年龄单性别贡献及口径解释；缺条件需澄清，不支持的指标需说明。任何额外 SQL 字段、非法枚举、格式错误或输出截断均不执行查询。结构校验并不能证明语义正确，遗漏用户条件仍需对照评测检查。

## 费用与失败控制

初始调用固定非思考模式，输出上限256 tokens，问题上限500字符，超时20秒，不自动重试。每次保存提供方 token usage 与耗时；缓存价格和时段会影响账单，估算不能当作实际账单。

30元是约定预算，不是当前代码已实施的全局硬上限。先只做本地、显式授权的小批测试；公开页保持规则模式。后续启用公开模型入口前，必须补服务端鉴权、持久化用量与额度控制，会话次数限制不能当作全局预算保护。

调用失败明确返回 model_error，不静默用规则答案冒充模型成功；允许用户手动切回规则版。

## 下一步评测

开发问题位于 evals/query_dev.json；这些题在编写提示词时可见，不能标成独立测试。先运行 `python scripts/evaluate_query.py --mode rule --limit 10` 建立更宽的规则基线。模型真实测试为 `python scripts/evaluate_query.py --mode model --limit 5 --allow-paid`，需先配置环境变量；该命令最多发出5次请求、不自动重试。输出 CSV 逐题记录结果与真实 usage。没有配置密钥时记录 model_error，不能算正确。

准备同一批、由人工标注意图和参数的问题，涵盖原句、同义改写、条件缺失、分母冲突、越界问题。保留开发集与冻结测试集；测试集一旦用于改提示词，就不能继续宣称独立测试。

先测试5条付费请求，检查字段和用量，再决定扩大样本。分别报告计划匹配、最终状态、数字一致性、请求失败率、端到端耗时和 tokens。另以模拟传输测试超时与坏JSON；模拟结果与真实模型结果分别记录。不能把拒答数量或静默降级算作模型正确率。

用户试用记录必须来自真实试用，不虚构节省时间或访谈人数。包含任务、原来步骤、完成情况、困难与对应修改。

## 密钥

Windows 系统代理发现可能在网络请求前阻塞。2026-10-21 用户诊断中系统模式超时、直连无密钥请求返回401，说明当时直连接口可达。评测可显式传入 `--connection direct`，仅影响该次 Python 进程，不改全局代理且保留 TLS 验证；默认仍使用 system。不应将无密钥401诊断当作真实密钥无效。

只在本机环境变量或云端 Secrets 保存 API Key，不发送到聊天、不提交 Git。代码不会自动加载 .env。当前不需要为网页添加密钥，因为模型功能尚未公开。

官方接口依据：https://api-docs.deepseek.com/guides/json_mode/ 和 https://api-docs.deepseek.com/guides/thinking_mode/ 。模型名与价格在实际调用前复核。
